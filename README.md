# KINGGRIEF — сайт + админка (исправленный слой данных)

Рабочая реализация магазина привилегий KingGrief с **единым источником правды** для настроек.
Главная задача: правка в админке (`/admin/design`) мгновенно и гарантированно видна на
публичном сайте — включая IP сервера.

Разбор найденных багов и план переноса фикса в ваш проект: **[BUGREPORT.md](./BUGREPORT.md)**.

## Запуск

```bash
npm install
cp .env.example .env.local     # задайте ADMIN_PASSWORD и ADMIN_SESSION_SECRET
npm run dev                    # http://localhost:3000
```

Без переменных окружения проект работает на файловом хранилище `.data/settings.json`,
пароль по умолчанию — `kinggrief` (в админке показывается предупреждение).

## Проверки

```bash
npm run check:drift              # падает, если IP/ссылки/счётчики снова захардкожены
node scripts/e2e-sync-check.mjs  # «поменял в админке → видно на сайте»
```

## Страницы

| URL | Что делает |
|---|---|
| `/` | Главная: IP, статус, топ привилегий — данные читаются на каждый запрос |
| `/privileges` | 14 уровней + таблица сравнения (все числа вычисляются из каталога) |
| `/privileges/[slug]` | Страница уровня: состав с наследованием, цена, соседние уровни |
| `/admin/login` | Вход: пароль + опциональный TOTP, лимит попыток |
| `/admin/design` | Редактор настроек, предпросмотр адреса, журнал изменений |
| `/api/settings` | `GET` (no-store) / `PUT` (нужна сессия, валидация, revalidate) |

## Хранилища

- **Supabase** (production): таблицы `site_settings` и `site_settings_audit` — см. `supabase/schema.sql`.
  Нужны `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` (service_role, не anon: при RLS + anon
  чтение вернёт пусто, и сайт молча покажет дефолт).
- **Файл** (локально/Node-хостинг): `.data/settings.json`, атомарная запись через временный файл.

## Почему IP больше не «залипает»

1. Значение живёт только в хранилище — ни в одном компоненте нет своей копии.
2. Публичные страницы объявлены `force-dynamic`, чтение из хранилища — на каждый запрос.
3. `/api/settings` отдаёт `no-store` + `Vercel-CDN-Cache-Control: no-store`.
4. `PUT` вызывает `revalidatePath('/', 'layout')`.
5. Клиент дополнительно опрашивает `/api/settings` (15 с, `focus`, `BroadcastChannel`),
   поэтому соседняя вкладка обновляется мгновенно.
6. Антирегресс: `npm run check:drift` не даст снова вписать домен в разметку.
