# KINGGRIEF — сайт + админка (исправленный слой данных)

Рабочая реализация магазина привилегий KingGrief с **единым источником правды** для настроек.
Главная задача: правка в админке (`/admin/design`) мгновенно и гарантированно видна на публичном
сайте — включая IP сервера — а сбой сохранения объясняется причиной, а не молчанием.

Разбор найденных багов и план переноса: **[BUGREPORT.md](./BUGREPORT.md)**.

## Запуск

```bash
npm install
cp .env.example .env.local     # задайте ADMIN_PASSWORD и ADMIN_SESSION_SECRET
npm run dev                    # http://localhost:3000
```

Без переменных окружения проект работает на файловом хранилище `.data/settings.json`,
пароль по умолчанию — `kinggrief` (в админке показывается предупреждение).

## Проверки

```bash
npm test                          # 28 юнит-тестов (валидация, каталоги, корзина)
npm run check:drift               # падает, если IP/ссылки/счётчики снова захардкожены
npm run check:cases               # сумма шансов каждого кейса = 100%
node scripts/e2e-sync-check.mjs   # сценарий «поменял в админке → видно на сайте»
```

## Страницы

| URL | Что делает |
|---|---|
| `/` | Главная: IP, статус, топ привилегий и кейсов — данные читаются на каждый запрос |
| `/privileges` | 14 уровней + таблица сравнения (все числа вычисляются из каталога) |
| `/privileges/[slug]` | Страница уровня: состав с наследованием, цена, соседние уровни |
| `/cases` | Все награды и шансы, проверка суммы 100%, наборы ключей |
| `/relics` | Пакеты риликов + калькулятор (цена за 1 000 вычисляется) |
| `/checkout` | Пересчёт заказа на сервере, уважает «магазин закрыт» из настроек |
| `/admin/login` | Вход: пароль + опциональный TOTP, лимит попыток |
| `/admin/design` | Редактор настроек, диагностика хранилища, журнал изменений |
| `/admin/diagnose` | Вердикт: работает ли сохранение, постоянно ли хранилище, что исправить |
| `/api/settings` | `GET` (no-store) / `PUT` (сессия, валидация, 409, revalidate) |
| `/api/settings/verify` | Самодиагностика: где хранится, доступна ли запись, круг «запись→чтение» |

## Если сохранение «откатывается»

Откройте `/admin/diagnose`. Типичный вердикт на Vercel без базы: «Сохранение настроек работать не
будет» — потому что каталог проекта только для чтения и `/tmp` не общий между инстансами.
Лечится только внешним хранилищем: Supabase (`SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`) и
`supabase/schema.sql`. Локально и на обычном сервере с диском файл `.data/settings.json` работает
постоянно.

## Хранилища

Каскад, выбранный при старте процесса:

1. **Supabase** — если заданы `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`
   (таблицы `site_settings` и `site_settings_audit`, см. `supabase/schema.sql`).
   Нужен именно `service_role`: при RLS + `anon` чтение вернёт пусто и сайт молча покажет дефолт.
2. **Файл** `.data/settings.json` (или `SETTINGS_FILE`) — атомарная запись через временный файл.
3. **Файл в `os.tmpdir()`** — если рабочий каталог только для чтения (serverless).
   Работает, но данные не переживают перезапуск: админка показывает «ограниченный режим».

## Почему сохранение больше не «молчит»

1. Кука сессии получает `Secure` только на реальном HTTPS — по HTTP браузер её не выбрасывает.
2. `PUT` принимает частичный payload и мержит с текущими настройками.
3. Ошибки хранилища различаются кодами (`SUPABASE_NO_TABLE`, `SUPABASE_UNREACHABLE`,
   `NO_WRITABLE_STORAGE`, `WRITE_FAILED`) и содержат действие для админа.
4. Оптимистическая блокировка по `updatedAt`: чужие правки не перетираются (409 + выбор).
5. Числовые поля не пропускают `NaN`.
6. Кнопка «Проверить сохранение» делает реальный круг «запись → чтение».
7. Публичные страницы `force-dynamic`, `no-store` на API, `revalidatePath` после записи.
8. Клиент синхронизируется по `focus`/`visibilitychange`/`BroadcastChannel`.
9. Устаревшая версия формы не блокирует сохранение: правка применяется (last-write-wins) с
   предупреждением; строгий режим доступен через `strict: true`.
10. HTML отдаётся с `no-store`, карточка адреса слушает `pageshow` (bfcache) — старый IP не
    остаётся на экране после «Назад».
11. Антирегресс: 28 тестов, `check:drift`, `check:cases`, E2E-скрипт с 21 проверкой.
