# KingGrief — Blender project

Вся 3D-сцена, персонажи, модели, окружение, анимация, камеры и свет созданы внутри Blender процедурным скриптом `build_trailer.py`. Это не Three.js-сцена и не набор смонтированных картинок.

## Файлы проекта

- `KingGrief_Trailer.blend` — редактируемая сцена Blender; таймлайн 100 секунд, 6000 кадров, выходные настройки 3840×2160 / 60 fps.
- `build_trailer.py` — генератор сцены и `.blend` (Blender/bpy 4.5+).
- `make_audio.py` — генератор оригинальной музыки и звуковых эффектов; нужен Python, NumPy и `imageio-ffmpeg`.
- `assets/KingGrief_Audio_Master.mp3` — общий стереомикс для фильма.
- `assets/KingGrief_Soundtrack.flac` — музыкальный stem.
- `assets/KingGrief_SFX.flac` — отдельный stem эффектов.
- `render_proxy.py` — выборочный быстрый прокси-рендер Cycles.
- `render_thumbnail.py` — сборка нативного 3840×2160 still из четырёх тайлов Cycles для меньшего пикового расхода памяти.
- `render_tiled_sequence.py` — отдельный нативный 4K-рендер фильма плитками; по умолчанию 12 временных выборок/секунду, чтобы снизить пиковую память.
- `encode_tiled_master.py` — сборка четырёх 4K-плиток, кодирование MP4 с аудио и оптическая интерполяция до 60 fps.
- `encode_master.py` — кодирование MP4 из обычной прокси-последовательности кадров.

## Открытие и полный рендер

Откройте `KingGrief_Trailer.blend` в Blender 4.5 или новее. Сцена настроена на Cycles CPU, 3840×2160, 60 fps; камеры переключаются маркерами на таймлайне. Для вывода нативной последовательности всех 6000 кадров используйте Render Animation из Blender. Это очень тяжёлый рендер; итоговое время зависит от железа.

Для нативного пространственного разрешения 4K последовательность рендерится плитками:

```bash
blender --background --python render_tiled_sequence.py -- --fps 12 --samples 1 --out /tmp/KingGrief_4K_Tiles
python3 encode_tiled_master.py --tiles /tmp/KingGrief_4K_Tiles --fps 12 --duration 100
```

Этот режим сохраняет каждый пространственный кадр из Blender в 3840×2160, но временные выборки выполняются при 12 fps и затем оптически интерполируются до 60 fps. Это честно указано в MP4 metadata; промежуточные кадры не являются отдельными рендерами Blender. На доступном CPU полный 100-секундный рендер может занять много часов.

Для быстрого прокси-превью (не нативные 4K-пиксели) используйте:

```bash
blender --background --python render_proxy.py -- --fps 12 --width 960 --height 540 --samples 1 --out /tmp/KingGrief_Base_Frames
python3 encode_master.py --frames /tmp/KingGrief_Base_Frames --fps 12 --duration 100
```

У сохранённого `.blend` стоит полный целевой режим 3840×2160 / 60 fps. Отрендерить все 6000 кадров непосредственно в Blender — наиболее строгий вариант, но он существенно медленнее tiled-пресета.

## Таймлайн

- 00–08 — осенняя долина, титр KingGrief и имена авторов.
- 08–22 — мастерская, вращающаяся шестерня, сундук и реликвии.
- 22–35 — стилизованный пролом/TNT-рейд.
- 35–49 — дуэль и удары скрещивающихся мечей.
- 49–60 — сбор команды на деревянном мосту.
- 60–72 — три медные фигуры на ярусах, установка золотой звезды и зажигание огней снизу вверх.
- 72–87 — широкий показ заснеженной площади.
- 87–100 — крупный финальный знак с `kinggrief.pickme.cloud`.

В сценах открытия указаны `_qwerty_70`, `domep444543`, `mistrKristalik`. Финальный адрес набран геометрией/текстом Blender и встроен в декорацию мира.
